# 激进删除无用代码设计

## 背景

当前仓库已经在 README 中明确主线为“已有账户 Plus 新流程”。旧的自动注册 Free 账号、手机号注册、多注册迁移设计、独立贡献流程已经不再作为当前功能维护，但代码中仍保留大量兼容模块、旧入口、旧界面和测试。

本次清理采用“主线收缩”方案：删除不服务当前主线的历史代码，同时保留 README 仍承诺的 Plus 支付链路和辅助能力，避免把当前可用功能误删。

## 保留范围

保留以下当前能力：

- 已有账户登录，包括账户 JSON 解析、登录页识别、密码提交和登录验证码提交。
- 登录验证码接口读取，包括 `mailbox_url` 拉取和验证码解析。
- Plus Checkout 创建，包括云端支付转换和本地页面创建回退。
- PayPal Hosted Checkout、GoPay、GPC 三类当前支付能力。
- Plus 成功确认、运行记录、自动运行停止与恢复。
- IP 代理、账号记录、本地 helper、云端 checkout converter 等 README 中仍声明的辅助能力。

## 删除范围

优先删除以下历史能力：

- 旧 Free 自动注册链路，包括注册邮箱预取、注册验证码、姓名生日资料填写等只服务注册的逻辑。
- 手机号注册链路，包括接码 provider、手机号注册步骤、手机号国家选择和注册后绑定邮箱重登分支。
- 贡献模式和独立贡献 OAuth 流程，包括侧边栏贡献模式 UI、后台贡献接口适配和相关消息入口。
- SUB2API / CPA / VPS 旧面板兼容入口中不服务当前 Plus 主线的部分。
- 旧邮箱生成和邮箱池 UI 中只服务注册的部分，包括自定义邮箱池、临时邮箱 provider、旧注册邮箱状态。
- 未被 `manifest.json`、`background.js` 当前主线、`sidepanel/sidepanel.html` 当前界面引用的 content script、sidepanel 模块、测试和文档图片。

## 处理策略

1. 先建立入口依赖清单，以 `manifest.json`、`background.js`、`sidepanel/sidepanel.html`、当前测试为根节点。
2. 按功能删除旧文件，并同步移除 `importScripts`、HTML `<script>`、消息路由、默认状态字段和界面字段。
3. 对大型文件中的旧分支采用小步删除，优先删除清晰不可达或由能力开关永久关闭的代码。
4. 同步更新中文文档，避免 README 和文件结构说明继续引用已删除模块。
5. 更新测试：删除只验证旧功能的测试，保留并补齐当前主线回归测试。

## 风险控制

- 动态消息和 Chrome 扩展运行时依赖不容易完全静态分析，因此每次删除后要运行现有 Node 测试。
- `background.js` 体量较大，删除默认状态字段和消息处理时必须同步检查侧边栏读取，否则可能出现保存配置失败。
- GoPay、GPC、IP 代理虽然不是最小链路，但仍属于 README 当前能力，本轮不删除。
- 历史本地配置字段删除后，旧用户数据会被忽略；这是激进清理的预期结果，但不能影响当前账户 JSON、支付配置和账号记录。

## 验收标准

- Chrome 扩展入口文件不再引用已删除文件。
- README 和项目文件结构说明不再列出已删除模块。
- 当前 Plus 主线测试通过。
- 代码中不再保留明显只服务旧注册、手机号注册、贡献模式的入口和 UI。
- 新增或保留的注释均为中文，必要边界条件有原因说明。
