# 错误重试分层策略

本文档说明当前已有账户 Plus 新流程的重试语义，避免把“节点内恢复 / Checkout 重建 / 自动运行轮次重试”混在一起理解。

## 1. 第一层：节点内恢复

定义：不离开当前节点，在当前页面或当前接口调用范围内恢复。

典型位置：

- `background/steps/existing-account-login.js`
- `background/steps/fetch-existing-login-code.js`
- `background/steps/create-plus-checkout.js`
- `background/steps/gopay-manual-confirm.js`

常见动作：

- 认证页临时状态不可识别时等待并重新检测。
- `mailbox_url` 短时间没有返回验证码时继续轮询。
- Hosted Checkout 验证码弹窗出现后按配置延迟再取码。
- GPC 远端任务等待 OTP / PIN 时更新手动确认状态。

## 2. 第二层：Checkout 重建

定义：当前账号仍在同一自动运行尝试中，但支付页或远端任务已经不可恢复，需要回到 `plus-checkout-create` 重新创建 Checkout 或任务。

触发来源：

- Hosted Checkout 页面失效、跳转异常或支付页卡死。
- 云端支付转换接口返回可重试错误。
- GoPay / GPC 订阅任务处于可重建失败状态。

特点：

- 不重新登录账号。
- 不重新读取账户 JSON。
- 有次数上限，连续重建失败后交给自动运行外层处理。

## 3. 第三层：自动运行尝试重试

定义：由 `background/auto-run-controller.js` 处理当前轮次的下一次 attempt，或进入下一轮账号运行。

典型场景：

- 账户 JSON 无效。
- 登录失败且无法在认证页恢复。
- 验证码接口持续无效。
- Checkout 重建达到上限。
- 用户开启 `autoRunSkipFailures` 后，需要跳过失败账号继续后续轮次。

## 4. 分类优先级

1. 能在当前节点恢复的错误，优先节点内恢复。
2. 支付页或任务不可恢复时，才重建 Checkout。
3. Checkout 重建仍失败，才交给自动运行 attempt / round。
4. 用户点击停止后，任何旧的倒计时、旧恢复入口和旧重试链路都不能重新拉起当前流程。

## 5. 当前重点错误

- `账户 JSON 缺少 email / password / mailbox_url`：配置错误，不进入页面流程。
- `接口返回中未找到有效验证码`：验证码接口返回格式不符合要求，优先检查 `code`、`data.code`、`result.code`。
- `云端支付转换失败`：按错误类型判断是否重试，超过上限后回到外层失败处理。
- `Hosted Checkout 页面提交后长时间未跳转`：优先判断是否可重建 Checkout。
- `GPC 任务失败 / 过期 / 取消`：清理当前任务运行态后结束当前支付节点。

## 6. 日志判断

日志正文只用于展示。步骤归属必须读取结构化元数据：

- `nodeId`
- `stepKey`
- `step`

新增重试逻辑时，不允许通过解析日志正文来判断当前步骤。
