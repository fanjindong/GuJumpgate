# 公告书写标准

本文件用于约束 AI 生成 GuJumpgate 相关公告时的 Markdown 格式。

## 使用方式

1. 先把这份文件内容发给 AI。
2. 再补充本次要发布的实际事项。
3. 要求 AI 严格按本文格式输出完整 Markdown。
4. 将结果放到对应公告或发布说明入口。

## 1. 公告用途

公告用于发布以下信息：

- 新版本发布。
- 已有账户 Plus 流程调整。
- PayPal Hosted、GoPay、GPC 支付能力变化。
- 云端支付转换服务变化。
- 已知问题说明。
- 临时维护通知。
- 用户需要执行的配置变更。

公告不是教程，不需要展开成长文。

## 2. 总体要求

AI 生成公告时必须满足：

1. 使用标准 Markdown。
2. 不使用 HTML 标签。
3. 标题明确，首段直接说明本次公告主题。
4. 优先写结论，再写细节。
5. 语气清晰、正式、简洁。
6. 尽量让用户在 10 秒内看懂重点。
7. 不写旧流程教程，不把历史注册链路当作当前能力。

## 3. 标准结构

```md
# 公告标题

一句话概述本次公告核心内容。

## 本次调整

- 要点 1
- 要点 2

## 影响范围

- 影响项 1
- 影响项 2

## 用户需要做什么

- 用户动作 1
- 用户动作 2

## 补充说明

补充说明内容。
```

不是每次都必须写满所有章节，但至少要保证：

- 有一级标题。
- 有概述。
- 有要点列表。

## 4. 标题规范

推荐标题：

- `# 已有账户 Plus 流程更新说明`
- `# PayPal Hosted Checkout 配置调整`
- `# GPC 自动模式维护通知`
- `# 云端支付转换服务更新`

不推荐：

- `# 说个事`
- `# 看一下`
- `# 更新了`

## 5. 正文写法

第一段必须直接说清：

- 发生了什么。
- 对谁有影响。
- 是否需要用户操作。

示例：

```md
GuJumpgate 已调整 PayPal Hosted Checkout 的验证码等待策略，使用 PayPal 支付方式的用户需要重新确认验证码接口配置。
```

重要事项优先使用短列表：

```md
## 本次调整

- PayPal Hosted 接码池支持按号码记录使用次数。
- 云端支付转换开启时，本地支付转换代理不再生效。
- 账户 JSON 仍需包含 `email`、`password`、`mailbox_url`。
```

涉及文件名、路径、接口、命令时必须用反引号包裹：

- `README.md`
- `services/checkout-converter/README.md`
- `POST /api/checkout`
- `start-hotmail-helper.command`

## 6. 禁止项

AI 生成公告时禁止：

- 使用 HTML。
- 写超长大段无分段文字。
- 写模糊时间词但不写清上下文。
- 写成教程。
- 写成 PR 描述。
- 写内部开发者视角内容。
- 把已下线的旧注册流程写成可用入口。

不要写：

- “这个地方我改了一下”
- “目前来说应该差不多”
- “可能有点问题后面再看”

## 7. 固定指令

把下面这段直接发给 AI：

```md
请帮我写一份 GuJumpgate 公告，严格遵守以下要求：

1. 输出必须是 Markdown
2. 不要使用 HTML
3. 风格简洁、正式、清楚
4. 先写结论，再写细节
5. 重要信息尽量用短列表
6. 涉及文件名、路径、接口、命令时用反引号包裹
7. 不要写成长教程
8. 不要写内部开发过程
9. 不要把旧注册流程写成当前可用能力

请按以下结构输出：

# 标题

一句话概述

## 本次调整

- ...

## 影响范围

- ...

## 用户需要做什么

- ...

## 补充说明

...
```
